# Five-scenario DCF, EDCA, and RL comparison

This is a fresh evaluation of exactly five workloads. Scenarios 1-3 reproduce selected historical workloads (original scenarios 5, 18, and 24); scenarios 4-5 are new workloads. It is not the historical 40-scenario result.

- Run: `1`; seed: `12345`; simulation: 60 s; measurement window: 59 s.
- RL checkpoint: `rl/q_table_v2.json`; retraining: none (completed v2 checkpoint reused).
- Each corresponding scenario uses the same traffic parameters, seed, and run in all three methods; only the MAC/access-control implementation differs.

DCF and RL use the ns-3 constant-rate finite-byte UDP source with `SeqTsSizeHeader`; EDCA uses its equivalent UDP sender to attach the selected TID. Packet size, generated byte limit, rate, timing, sequence/timestamp header, stations, and measurement interval are matched. The EDCA TID/MAC access category is part of the access-control method under comparison.

## Interpretation and limitations

These results describe only the five specified workloads, one run and one seed per workload, and the selected checkpoint. Scenarios 1-3 were selected historical workloads, including workloads previously identified as RL wins; this selection creates post-hoc selection bias. Scenarios 4-5 are new, but only one run per scenario was measured. This is not evidence that RL outperforms DCF or EDCA across the original 40 scenarios or across general Wi-Fi workloads. A single run per scenario also does not quantify run-to-run variability.
